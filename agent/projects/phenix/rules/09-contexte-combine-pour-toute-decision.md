# contexte combiné pour toute décision

CONTEXTE COMBINÉ. Toute réponse, décision, brouillon, préparation de réunion ou triage d email part du Copilote (lib/copilote du dépôt ai-ready), pas d une recherche Drive. 1) INDEX : au début de chaque tâche, si COPILOTE_DB (scratchpad/copilote.sqlite) est absent ou plus vieux que le dernier pack kb, exporter la collection kb (et docs de Qui contacter) en fichiers {chunks:[…]} puis « npm run copilote -- ingest <dossier> » (les xlsx générés par nous : convertir en .md). 2) RECHERCHE : lancer « npm run copilote -- search » avec 2 à 4 formulations (référence MGEN/A-0xx, noms, IP, sigle) et lire les passages : emails, documents, suivi, annuaire, infos orales d Issam, ensemble. 3) RÉPONSE : combiner ces passages, citer chaque fait (email Nom jj/mm, document vX p.N, Issam oral jj/mm), marquer « Déduction : » ce qui croise plusieurs sources, dire « pas dans la base » plutôt que deviner. Gmail ou Drive seulement pour un fait plus récent que la base, et on l indique. 4) INGESTION SANS DÉLAI : chaque email Phénix lu (pas seulement les fils lus en entier), chaque document reçu et chaque info donnée par Issam en séance devient un extrait dans un pack kb le jour même (durable) et est ajouté à l index local. 5) RATTRAPAGE : les fils Phénix depuis le 01/11 (≈200) sont indexés par lots de 20 à chaque veille jusqu à épuisement ; noter le lot dans jour.passages.

_Source : Issam, 19/11 : « Everything : email, doc et info fournie doivent être accessibles on the spot et combinés pour toute prise de décision »_
